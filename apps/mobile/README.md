# مصحف تميمي — تطبيق Expo

نسخة الجوال المستقلة لمصحف تميمي، مبنية بـ Expo Router وReact Native وTypeScript. يستخدم التطبيق SQLite لعرض نص المصحف من قاعدة محلية مضمّنة، ويحفظ الإشارات المرجعية على الجهاز. لا يستبدل هذا التطبيق نسخة Capacitor الموجودة في جذر المستودع.

## المرحلة الأولى

- الصفحة الرئيسية مع متابعة آخر موضع قراءة.
- فهرس السور والأجزاء مع بحث محلي.
- قراءة السورة من قاعدة SQLite دون اتصال، مع التنقل بين السور وحفظ موضع القراءة.
- إعدادات العربية/الإنجليزية، السمات الورقية والفاتحة والداكنة، وحجم خط المصحف.
- واجهة RTL عربية افتراضيًا، وخطا Amiri Quran وTajawal.
- تصدير ويب ثابت قابل للتثبيت كـ PWA، مع تخزين مؤقت لهيكل التطبيق والموارد التي تُفتح أثناء الاتصال.

تتضمن قاعدة البيانات النص العربي فقط؛ لم تُضمّن ترجمة Saheeh International لأن مستودع المشروع يطلب التحقق من إذن إعادة نشرها. يظهر إسناد corpus وترخيصه في قسم «حول التطبيق».

## المرحلة الثانية

- البحث المحلي عن كلمات الآيات دون تشكيل، مع دعم اختلافات الألف وأرقام السور والآيات. لا يبحث التطبيق في ترجمة إنجليزية غير مضمنة.
- إشارات مرجعية محلية لكل آية، مع ملاحظة وتصنيف ولون، وإمكانية تصديرها واستيرادها بصيغة JSON.
- الضغط على آية يفتح لوحة تفاصيل بتبويبات التفسير والإعراب والإشارة المرجعية؛ وتُحفظ بيانات الإشارات في SQLite.
- جهّزت طبقة البيانات جداول منفصلة للتفسير والإعراب، وتشترط بيانات المصدر والترخيص والرابط الآمن. لا توجد حزمة تفسير أو إعراب مضمّنة حاليًا: لم يُتحقق من ترخيص إعادة نشر مورد محدد، لذلك تُظهر الواجهة حالة عدم التوفر بدل اختلاق نص أو نسبته إلى مصدر. يمكن ربط مزود بيانات موثق لاحقًا عبر عقد المستودع بعد التحقق من حقوقه.

## المرحلة الثالثة

- مشغل صوت مستمر على مستوى التطبيق مع تشغيل في الخلفية، شاشة القفل، التحكم بالتشغيل، التنقل 10 ثوانٍ، وسرعة تشغيل متغيرة.
- مكتبة محلية تُضيف إليها ملفات MP3 أو M4A أو AAC أو WAV أو OGG من الجهاز، وتربط كل ملف بسورة واسم قارئ. تُنسخ الملفات إلى مساحة التطبيق الخاصة ليظل الاستماع دون اتصال، ويمكن حذفها من المكتبة.
- تكرار السورة أو تكرار مقطع زمني يحدده المستخدم بالثواني. لا يوجد ربط تلقائي بالتوقيتات أو تكرار آية؛ لا توجد بيانات توقيت مرخّصة مضافة.
- لا يتضمن APK تسجيلات صوتية؛ لم يُتحقق من حقوق إعادة توزيع تسجيلات محددة. استورد فقط الملفات التي يحق لك حفظها وتشغيلها؛ تبقى الملفات محليًا ولا تُرفع. ينتقل المشغل بعد انتهاء السورة إلى السورة التالية المتوفرة للقارئ نفسه.
- يحتاج التشغيل الخلفي إلى إعداد `expo-audio` في `app.json` وإلى شاشة القفل لتفادي إيقاف Android للتشغيل الممتد.

توزيع الآيات داخل إطار القراءة متجاوب، وليس ترقيم صفحات مصحف المدينة؛ لا تُعرض أرقام صفحات معيارية غير متوفرة في البيانات الحالية. ألوان التجويد والحساب والمزامنة والإشعارات ما زالت خارج التنفيذ.

## التشغيل والتحقق

من جذر المستودع:

```powershell
cd apps/mobile
npm install
npm run start
```

لتشغيل نسخة الويب محليًا: `npm run web`. يتطلب التثبيت والعمل دون اتصال استضافة HTTPS؛ افتح التطبيق مرة أخرى بعد تحميله أول مرة حتى يتحكم عامل الخدمة بالصفحة، والموارد التي لم تُحمّل أثناء الاتصال لن تكون متاحة دون إنترنت. للتحقق من TypeScript وسلامة قاعدة البيانات:

```powershell
npm run check:types
npm run lint
npm run test:search
npm run test:data
npm run export:web
```

أُنشئت قاعدة البيانات مباشرة من corpus المضمّن مسبقًا في `www/index.html`، من دون توليد نصوص قرآنية أو إعادة تنسيقها. يُثبت الاختبار الموجود في `tests/quran-data.test.cjs` عدد السور والآيات وبصمة النص العربي للمصدر، ويقارن اختبار التطبيق نسخة SQLite بالمصدر. الترخيص والإسناد موثّقان في `NOTICE.md` في جذر المستودع. اختبارات التطبيع وصيغة الإشارات في `tests/arabic-search.spec.mjs` و`tests/test_mobile_schema.py`.

## إخراج APK / AAB

بعد تسجيل الدخول وربط التطبيق مرة واحدة (`npx eas-cli@latest build:configure` داخل `apps/mobile`):

```powershell
npm run build:apk
npm run build:aab
```

ملف `eas.json` يعرّف `preview` لتوزيع APK داخلي و`production` لإخراج AAB. يعيد EAS رابط الملف بعد اكتمال البناء. يتطلب البناء السحابي حساب Expo وإعداد المشروع؛ لم يُضمّن معرّف مشروع EAS أو بيانات اعتماد.

لبناء APK تجريبي قابل للتثبيت دون حساب EAS، شغّل سير عمل GitHub Actions **Build Expo APK** يدويًا على الفرع المطلوب. ينتج سير العمل APK موقّعًا بمفتاح debug ويرفعه كـ artifact باسم `tamimi-mushaf-debug-apk` لمدة سبعة أيام. هذه نسخة اختبار للاستخدام المباشر، وليست إصدار متجر Google Play.

تحتاج نسخة الويب إلى ترويسات `Cross-Origin-Embedder-Policy: credentialless` و`Cross-Origin-Opener-Policy: same-origin` كي يعمل SQLite/WASM. أُضيفت للـ Metro وأُعدّت عبر إضافة Expo Hosting؛ عند استخدام استضافة أخرى، اضبط الترويسات نفسها لدى مزوّد الاستضافة.

## التعديل

- الهوية، اسم التطبيق، ومفاتيح الميزات ومعلومات مصادر corpus وحالة حزم الشروح: `src/config.ts`.
- رسومات الهوية المخصصة: `python scripts/generate-brand-assets.py` (لا تحتاج مكتبات صور خارجية).
- ألوان السمات والخطوط والمسافات والزوايا: `src/theme.ts`.
- نصوص العربية والإنجليزية: `src/i18n.ts`.
- بيانات القراءة والفهرس والبحث والإشارات ومستودعات التفسير والإعراب: `src/data/quran-repository.ts`. استمر باستخدام `QuranRepository` عند تغيير طبقة البيانات.
- بناء قاعدة البيانات محليًا بعد تغيير corpus الموثوق: `python scripts/build-quran-db.py` من هذا المجلد، ثم شغّل اختبارات البيانات.

## المراحل التالية

1. **المرحلة الثالثة:** اكتملت تلاوة الملفات المحلية والتشغيل في الخلفية؛ لا توجد تسجيلات مضمّنة.
2. **المرحلة الرابعة:** ألوان التجويد والتفسير الموضوعي.
3. **المرحلة الخامسة:** الحساب والمزامنة والإشعارات واقتراح الميزات.

تظل هذه المراحل خارج نطاق التنفيذ الحالي حتى موافقة المستخدم. لا تُفعّل ميزاتها أو تضع بيانات تجريبية على أنها موثوقة.
